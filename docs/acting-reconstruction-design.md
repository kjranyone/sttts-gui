# 発話の表現を再構築する設計と実装状況

更新: 2026-10-09

## 目的と境界

sttts は、話した内容を選んだ別の声で届ける。その際、文字だけでは失われる速さ、間、感情の候補を発話単位で Irodori-TTS に渡す。「表現を反映する」は元の演技の**再解釈**であり、音高曲線、語ごとの長さ、息遣いを厳密に複製する機能ではない。声の同一性は利用者が選んだ参照音声・声の設定で保ち、元の発話を Irodori の参照音声へ差し替えない。

主経路の文字起こしは Gemini Transcribe Live とする。ローカル ASR は利用者が明示的に選ぶ用途として残すが、Gemini の失敗時に自動で切り替えない。確定転写も誤認識し得るため、利用者は音声キューの「自動再生」を ON/OFF できる(OFF ではカードで確認してから話す)。文字入力には元音声がないので、自動音響分析は適用せず、利用者が入力した絵文字と声の設定を使う。

## 現在の実装

| 領域 | 現状 |
| --- | --- |
| 準リアルタイム転写 | ローカル VAD の開始時に発話専用の Gemini Live 接続を開き、16 kHz PCM を録音中から約 100 ms 単位で送る。開始判定より前の最大約 160 ms も含める。途中転写を GUI に出し、VAD 終了で audio_stream_end を送り、確定文を待つ。 |
| 原文 | Gemini の VERBATIM を既定にする。確定文字列を発話カードに保持し、合成用の絵文字を原文へ書き戻さない。現状、原文と別の整形済み読み上げ文は持たない。 |
| 音響観測 | VAD 確定後、元音声のコピーから発話長、活動時間、RMS、長い無音の合計を軽量計算する。確定文のモーラ数と活動時間から速度を求め、最近の発話の中央値と比較する。分析は ASR の確定待ちと並行して行う。 |
| 感情候補 | emotion2vec+ は Python 専用だったため、Rust 版では未対応(`pipeline.emotion_engine` は `none` のみ)。分類器を足すときは明確な分類だけを五つの表現へ写し、スコアを感情の確率として表示しない。 |
| 合成計画 | 発話単位の Delivery に絵文字、短いスタイル文、duration_scale、出所を保持する。転写文とは別に GUI⇄backend プロトコルで運び、確認後の発話と再発話にも引き継ぐ。 |
| Irodori 入力 | TTS の各チャンクの先頭へ選んだ絵文字を付け、声の既定 caption に今回のスタイル文を加え、duration_scale は今回のジョブだけに適用する。選択中の参照音声は維持する。 |
| GUI | 「テンポと間を再現」を ON/OFF し、発話カードで原文と適用表現を分けて表示する。文字入力欄の絵文字パレットと直接入力で Irodori の対応絵文字を指定できる。 |

Gemini Live が返すのは途中・確定転写であり、感情や単語単位の時刻はこの経路から得ない。[Gemini Live Transcribe の仕様](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe)を前提に、表現は元音声の別解析で得る。Irodori へ渡す絵文字の対応、手動入力、設定例は[Irodori への表現指示](irodori-annotations.md)にまとめる。

## 発話のデータ経路

1. 音声ソース → 16 kHz → silero VAD。マイクは ASR ロードと並行して先に開き、レベルメーターを維持する。VAD スレッドは Gemini への音声投入だけを行い、WebSocket の応答や表現モデルを待たない。
2. VAD 開始で Gemini の発話 ID によるストリームを作り、先行バッファと以後の PCM を送る。途中転写を表示する。VAD 終了でストリームを閉じ、同じ発話 ID の音声を表現分析へ渡す。
3. ASR ワーカーが確定文を受け取る。表現分析は最大 150 ms だけ待つ設定を既定とし、間に合わなければ表現なしで進める。空の転写や ASR エラーでは自動発話しない。
4. 発話 ID と確定文に Delivery と無音合計を添えて GUI へ送る。自動発話時はすぐに TTS ジョブを作る。確認方式では GUI が Delivery を保持してから発話要求に添える。
5. TTS は従来のチャンク順序、キャンセル、再生規則で合成する。元音声の配列は backend 内でのみ扱い、GUI プロトコルとログへ載せない。

現状の音響計算は VAD 確定後に一回実行する。録音中の逐次音響計算や、句ごとのアラインメントは実装していない。無音合計は GUI プロトコルに載せるが、発話カードにはまだ表示しない。

## 表現の判断と失敗時の動作

- 話者内の直近三発話以上で速度の基準が得られ、大きく速い・遅い場合だけ、Irodori の ⏩／🐢 と控えめな長さ倍率を選ぶ。長い発話内の間が多ければ、caption に「間を取りながら」を加える。特定の語の位置へ ⏸️ を自動挿入しない。
- emotion2vec+ の happy、sad、angry、fearful、surprised だけを、明確な判定のときに対応絵文字と短いスタイル文へ写す。neutral、unknown、other、disgusted や曖昧な判定には感情を付けない。音量だけから感情を断定しない。
- 利用者が文字欄へ入れた絵文字はそのまま合成テキストへ渡す。自動推定より利用者の入力を優先する。感情モデルは別途導入・設定が必要で、モデル未設定や解析期限超過時にも確定文の読み上げは継続する。
- 投機的 TTS を明示的に有効にした場合、先頭チャンクの一致を優先するため、その発話には自動表現分析を適用しない。これにより、異なる表現条件で先行合成したチャンクを再利用しない。
- セッション停止では Gemini の発話ストリームを中断・回収し、マイクを解放してから次の開始へ進む。停止後の再開には既存のクールダウンを使う。

## 現時点の制約と次の評価

Gemini Live に語単位の時刻がないため、元音声の間を転写文の特定箇所へ対応付けたり、句ごとに別の感情・速度を与えたりはしない。発話カード上で推定タグだけを個別に修正する UI も未実装。全体の表現反映切替、転写文の訂正、文字欄への絵文字入力を使う。Irodori の絵文字、caption、duration_scale の効果も確定的ではなく、選んだ声やモデルで変わる。[Irodori 公式パラメータガイド](https://github.com/Aratako/Irodori-TTS/blob/main/docs/parameters.md)

次の評価対象は、同じ文を異なる話し方で発した組を使う内容の正確さ、表現の識別しやすさ、声の一貫性、自然さ、初音までの時間である。emotion2vec+ の日本語音声での誤推定と CPU 時間、Gemini のネットワーク遅延、Irodori の表現の効き方は実音声で未測定。句単位の再構築が必要なら、追加のアラインメント手段と遅延・費用を評価する。忠実な韻律追従が要件になった場合は、音声変換または韻律条件付き合成を別経路として検討する。

製品判断として、原文の言い直し・フィラーをどこまで読み上げるか、表現改善に許せる初音遅延、声の自然さと演技反映の優先順位は実音声の比較結果を見て決める。

検証は fake source・fake VAD・fake Gemini サーバ・mock TTS を注入した `crates/engine` のテストまで。実マイク、実 GPU、Gemini API、実 Irodori の組み合わせは自動テストでは動かしていない。実デバイス確認は[ハードウェア検証ポリシー](../AGENTS.md)に従う。
